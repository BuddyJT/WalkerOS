Image choices

Offer Lite and Full downloads when builds are ready.

Both images should use the same Walker OS identity and setup flow. The difference is where data and heavier work live after first boot.

Walker OS Lite Cloud-ready

Small image for Raspberry Pi hardware

Designed to avoid bottlenecks on low-RAM devices by using Nextcloud, Google Drive, iCloud, Dropbox, or business cloud storage for large files, backups, transcripts, and indexes.

  • Minimal local service footprint
  • Cloud or personal-cloud storage wizard
  • Safe defaults for limited RAM and disk
  • Queue heavy work instead of locking up the device
Walker OS Full Local-first

Full image for stronger hardware

Runs the Lite workflow as an option, but defaults to storing memory, documents, indexes, backups, and automation state on local hardware.

  • Local knowledge and file indexes
  • On-device backups and rollback targets
  • Heavier automation workers and monitoring
  • Optional cloud sync, not required cloud storage

Image build plan

What the repo should generate.

The previous Walker Pi task established the build shape: a small upload-ready repo, not a giant committed disk image.

Build tool

rpi-image-gen

Use Raspberry Pi image generation from a Linux runtime, likely through Docker, OrbStack, or WSL2 for Windows later.

Image target

walker-zero2w.img

Start with Raspberry Pi Zero 2 W, then add Pi 5 and broader Linux targets as real testing grows.

Base layers

rpizero2w, image-rpios, trixie-minbase

Keep the first system compact and focused before adding heavier desktop or AI workloads.

Walker layer

walker-base

Install service directories, logs, SQLite memory, backup timer, status command, and placeholder app launcher.

Release checklist

Do not ship mystery images.

Every public release should prove the image builds, flashes, boots, exposes secure access, starts Walker, writes logs, and can be restored.

Check What to verify Why it matters
Source Shell scripts parse, YAML loads, workflow checks pass Prevents simple packaging errors
Build Image exists, partition table is valid, checksum is recorded Buyers can verify downloads
Hardware Pi boots, network appears, SSH works, Walker service is active Marks a release as physically tested
Release Upload image as a release asset, not a normal repo file Keeps GitHub clean and manageable
