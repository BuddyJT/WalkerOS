Runtime profiles

Lite and Full should share the same core, but store data differently.

Walker OS should not force every device to carry the same workload. The edition profile should decide where memory, files, indexes, backups, and heavy processing live.

Lite profile

Prevent bottlenecks on constrained hardware

  • Keep local services small: dashboard, command router, auth, logs, and device telemetry
  • Use cloud or personal cloud storage for documents, backups, transcripts, and large memory indexes
  • Prefer queued tasks and remote processing when RAM, CPU, or disk pressure gets high
  • Target Raspberry Pi Zero 2 W, Pi 4, small thin clients, and travel hardware
Full profile

Run local-first when the hardware can handle it

  • Store memory, documents, indexes, backups, and dashboards on local disks by default
  • Offer Lite-style cloud sync as an optional mirror, not a requirement
  • Run heavier search, OCR, telemetry, local services, and automation workers on-device
  • Target Pi 5, mini PCs, desktops, servers, NAS boxes, and homelab nodes

Knowledge store

Memory should be inspectable, editable, and yours.

Walker OS should remember enough to be useful without hiding what it knows. Each entry needs a source, timestamp, confidence, category, update history, and whether the user provided it.

Stored knowledge

What Walker remembers

  • Facts and information
  • People, places, projects, tasks, notes, and documents
  • Devices, cloud accounts, services, settings, and preferences
  • Investments, financial notes, calendars, events, and important decisions
Entry metadata

What every memory contains

  • What it is, value, source, when learned, and last updated
  • Confidence, category, linked records, and relations
  • User-provided flag and visible edit/delete controls
  • Clear separation between local memory and optional cloud calls

Security and privacy

Always on, always visible.

Walker OS should protect the user before it shows off. Security is not a later feature; it is part of the first serious version.

Authentication

SSH key-based access, encrypted tunnels, no plain-text passwords, and granular permissions per device.

Monitoring

Threat detection, malware and ransomware scanning, file integrity, login monitoring, process behavior, and audit logs.

Control

Confirm destructive actions, fail safe rather than fail open, keep data under user control, and make shutdown obvious.
